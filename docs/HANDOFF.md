# Handoff for coding agents

Start here if you are a fresh coding agent (Claude Code, Codex or similar) taking over this repo. Read
[`AGENTS.md`](../AGENTS.md) too; its hard rules win if anything here disagrees. State as of Oct 18, 2026 (main `8ff25d4`).

## What the app is

ApniHealth is an open-source (AGPL-3.0), mobile-first, multi-user health record PWA for a household: profiles for
adults and children, illness episodes, medicines with reminders, appointments, a daily log (manual or Apple Health),
lab results with a trend explorer, uploaded reports, a child record, export and account deletion. It runs either as
a self-hosted Node server or on Cloudflare Workers. Not medical advice; never add any.

## Architecture

- **One request handler, two runtimes.** `app.mjs` is the shared handler (static files, `/api/...`, `/config.js`,
  `/members.css`, the landing page). It never listens and never starts timers.
  - Node: `server.mjs` listens on `127.0.0.1:$PORT` (default 4174) and starts `scheduler.mjs`.
  - Workers: `worker.mjs` + `wrangler.toml`. The Worker forwards every request to **one SQLite-backed Durable
    Object** (`ApniHealth`, id from name `instance`, EU jurisdiction unless `DO_JURISDICTION=none` in local
    tests). The DO migrates the database, installs the R2 blob backend and the assets backend, imports `app.mjs`
    and serves it through `cloudflare:node` `httpServerHandler` (the in-isolate server listens **once per isolate**;
    see the `listening` flag, it fixed an `EADDRINUSE` outage). `nodejs_compat` is required.
- **Storage.** `node:sqlite` (Node 22.13+) on Node. `db.mjs` owns the connection, migrations runner and transactions;
  `useDatabase()` installs another backend. `sqladapter.mjs` is the synchronous storage interface with two backends:
  node:sqlite and the Durable Object (`ctx.storage.sql`). DO SQLite does not accept named-parameter objects (it binds
  them silently as `[object Object]`), so the adapter translates `$name` to positional `?` and refuses objects;
  `tx()` maps to `transactionSync` (DOs refuse `BEGIN`/`COMMIT` and `PRAGMA journal_mode`). All member data goes through
  `store.mjs` `forMember(id)` under an actor (`store.runAs`). Schema lives in `migrations.mjs` (currently up to
  version 10); add new versions, never edit released ones.
- **Blobs.** `blobs.mjs`: an async interface. fs backend under `private/profiles/<id>/...` on Node; R2 (`BLOBS`
  binding, EU jurisdiction) on Workers via `workers-backends.mjs`. Never use `node:fs` on profile files directly.
- **Static assets on Workers.** `[assets]` with `run_worker_first = true`, so auth, consent, security headers and
  the demo notice still apply. `public/index.html` and data files are generated by `python3 build.py`; build from a
  clean checkout with an empty `private/` before deploying.
- **Scheduler.** `scheduler.mjs` holds all periodic work (hourly purge, reminder `push.tick`). Node calls
  `startScheduler()`; the Workers Cron Trigger (`* * * * *`) calls `runScheduled()` in the DO. Never add another
  `setInterval`.
- **Mail.** `mailer.mjs`: Resend HTTP API when `RESEND_API_KEY` is set (works on both runtimes; the fetch uses
  `redirect:'manual'` because `redirect:'error'` throws on Workers), otherwise SMTP via `SMTP_URL` (Node only,
  `node:net`/`node:tls` imported lazily), otherwise sign-in links go to the server log (dev only). `MAIL_FROM` must
  be on a domain verified with the provider.
- **Push.** `push.mjs`: Web Push with built-in crypto, sent with `fetch`. VAPID key from `VAPID_PRIVATE_JWK`
  (Workers secret) or `private/vapid.json` (Node). Pass keys as JWK/PEM/DER, never a `KeyObject` inside an options
  object (fails on Workers).
- **Auth.** `auth.mjs`: `AUTH_MODE=builtin` (email links, passkeys via `webauthn.mjs`, sessions in `accounts.mjs`) or
  `trusted-proxy` (Cloudflare Access JWT, `access.mjs`). Fail closed; same-origin writes only; `APP_HOST` is the
  Host allow-list (other hosts get 400). `auth.mjs` `PUBLIC_PATHS` lists what signed-out visitors may load.

Plans with the reasoning behind all of this: [`docs/plans/workers-d1.md`](plans/workers-d1.md) (Workers port; the
name still says D1, but SQLite in a Durable Object was chosen) and [`docs/plans/report-ocr.md`](plans/report-ocr.md)
(reading lab reports; phase 1 built, phase 2 not approved).

## Key modules

`AGENTS.md` "Structure" lists every module. The parts most likely to need work:

- **Reading lab reports (OCR), all on the device:**
  - `public/labunits.mjs`: unit spellings, normalisation and conversions.
  - `public/labmap.mjs`: positioned text tokens -> lines -> rows -> catalog markers, with confidence buckets. Pure,
    tested in Node (`test-labmap.mjs`). Handles Indian grouping (2,50,000), restores a lost decimal point for lakh/µL
    counts only when the printed range supports it, and keeps ranges whose dash was dropped by OCR.
  - `public/report-extract.mjs`: pdf.js text for PDFs, tesseract.js OCR for photos/scans (eng+deu by default, hin on
    request, max 10 pages per run).
  - `public/report-review.mjs` + `report-review.css`: the mandatory review screen; unclear/unrecognised rows start
    unticked. The server only receives confirmed values (`POST /api/labs` with `uploadId`, `method`, `learn`).
  - `labs.mjs` (server side), catalog `config/markers.default.json`, household markers/aliases in `lab_markers`.
  - Third-party OCR files: pinned with sha256 in `public/ocr-assets.mjs`, downloaded by `scripts/vendor-ocr.mjs`
    into git-ignored `public/vendor/` (`--check` verifies). Fixtures are generated at test time
    (`scripts/make-report-fixtures.mjs`), never committed.
- **Dashboard:** `public/dashboard.js` (cards, sparklines, week-on-week) and `public/figure.js` (gender-neutral body
  figure, no face or hair, callouts only from the person's own readings, "No reading yet" otherwise; never sample
  values). Test: `test-browser-dashboard.mjs`.
- **Landing page:** `landing.mjs` (server-rendered, no scripts or inline styles) + `public/landing.css` (all motion in
  CSS). The figure `public/hero-figure*.webp/.jpg` is an AI-generated invented person (credited in README); its vitals
  are fixed sample values, labelled as such. Test: `test-browser-landing.mjs`.
- **Preview mode** (fictional data, screenshots): [`docs/preview.md`](preview.md).

## Run locally

Needs Node 22.13+ and Python 3. Use a scratch clone for preview data, never a folder with real data.

```bash
PREVIEW_MODE=1 node scripts/preview/seed.mjs && python3 build.py
PREVIEW_MODE=1 PREVIEW_AUTH_TOKEN=$(openssl rand -hex 16) NO_PUSH=1 PORT=4180 \
  node --import ./scripts/preview/loader.mjs server.mjs
node scripts/preview/screenshots.mjs /tmp/shots            # desktop.png + phone.png (needs CHROME_BIN)
```

A real self-hosted setup is in README "Set up" (`.env.example` lists the variables). Workers locally:
`node test-workers.mjs` runs the app under `wrangler dev` (local workerd, no account needed).

## Tests and CI

```bash
ci/check-syntax.sh            # syntax of every tracked file
node scripts/vendor-ocr.mjs   # OCR assets (needed by the OCR tests; cached in ~/.cache/apnihealth-ocr)
npm test                      # all unit tests (NO_PUSH=1), test-build-index.py, then test-server.mjs end to end
npm run test:browser          # Chrome at 390x844: smoke, dashboard, accounts, onboarding, landing, ocr, report-review
npm run test:workers          # wrangler dev end to end (npx wrangler@4.151.1)
```

Browser tests and `test-report-fixtures.mjs` need Chrome (`CHROME_BIN`). CI (`.github/workflows/ci.yml`) has two jobs:

- `checks`: gitleaks over full history (pinned, sha256-checked), syntax, OCR asset download, each unit test, server
  end to end, browser tests.
- `workers`: `node test-workers.mjs` under wrangler 4.151.1.

When you add a test file, add it to `package.json` **and** `ci.yml` (and the README test list). All tests use
fictional data only.

## Conventions

- Branch from `main`, keep PRs small, open them non-draft. **End every PR body with the line
  `MergeJudge-Actor: agent`.**
- Merge with a merge commit: `gh pr merge <N> --merge --body "MergeJudge-Actor: agent"`, only after CI is green
  **and the maintainer has said OK**. Never force-push, never rewrite pushed history; update a branch by merging
  `main` into it.
- **Service worker:** when shell files change (anything in `SHELL` in `public/sw.js`, or a new client file), bump
  `V` in `public/sw.js` (now `apnihealth-v16`) and add new client files to `SHELL`. Two open PRs that both bump `V`
  conflict; the second one takes the next number.
- **CSP:** no inline scripts, no `style="..."` (use the CSSOM). `'wasm-unsafe-eval'` is allowed only on the app page
  and `/vendor/ocr/` (`http.mjs` `appHeaders`) for OCR; never widen it or add `'unsafe-eval'`/`'unsafe-inline'`.
- **Vendored assets:** no committed third-party binaries; pin exact versions and sha256 in `public/ocr-assets.mjs`.
  New npm dependencies need a maintainer decision first.
- Never commit health or personal data, secrets, account ids or private infrastructure details (this repo is public).
- Be exact in PR descriptions about what you actually tested.

## Deploy (Cloudflare Workers)

**Merges to `main` deploy automatically.** `.github/workflows/deploy.yml` runs when the `CI` workflow finishes
successfully for a push to `main` (`workflow_run`), checks out that exact commit, builds it and runs
`wrangler@4.151.1 deploy`. It skips a commit that is no longer the tip of `main` (the newer one deploys after its own
CI), runs one deploy at a time (concurrency group `deploy`, never cancelled) and can be re-run by hand from the
Actions tab (`workflow_dispatch`, `main` only). So: merging is deploying. Only merge what is ready for users.

What the workflow does:

1. Fails early if a setting below is missing.
2. `node scripts/vendor-ocr.mjs` (pinned, sha256-checked OCR assets) and `python3 build.py` on a clean checkout
   with an empty `private/`.
3. Prints the current deployment (the rollback target), then deploys with all four `--var` values. `--keep-vars` is
   not enough: the `[vars]` defaults in `wrangler.toml` (demo name and notice) would replace the live values.
4. Prints the new version id (also in the run summary) and smoke-tests `https://$APP_HOST/` and `/login`.

What it needs (repository settings, environment `production`, limited to the `main` branch):

| Kind | Name | Value |
| --- | --- | --- |
| Secret | `CLOUDFLARE_API_TOKEN` | a token scoped to this account: Workers Scripts Edit, Workers R2 Storage Edit (add more only if a deploy asks for it) |
| Secret | `CLOUDFLARE_ACCOUNT_ID` | the Cloudflare account id |
| Variable | `APP_HOST` | the public hostname (requests for other hosts are refused) |
| Variable | `APP_NAME` | the product name shown in the app |
| Variable | `MAIL_FROM` | `Name <noreply@domain>` on a domain verified in Resend |
| Variable | `DEMO_NOTICE` | the banner text |

Worker secrets (`RESEND_API_KEY`, `VAPID_PRIVATE_JWK`) live on the Worker, not in GitHub, and survive deploys; set
new ones only with `wrangler secret put`, never print them. Changing a variable takes effect on the next deploy
(re-run the workflow).

**Roll back:** find the previous version id in the failed or newest run's "Previous version" step (or
`npx --yes wrangler@4.151.1 deployments list`), then `npx --yes wrangler@4.151.1 rollback <version id>` with a
token for the account. A rollback is undone by the next merge to `main`, so fix or revert on `main` too
(a revert PR, never a force-push).

Manual deploy (only if Actions is down): same steps from a clean checkout; if wrangler fails with `EACCES` on a cache
dir, set `WRANGLER_CACHE_DIR` to a writable folder. After any deploy, `wrangler tail` for a minute (cron runs, no
exceptions).

Migrations run automatically in the DO constructor on the first request after a deploy; they must be additive.

## Known limitations

- README's "Status: early" note and Roadmap are partly out of date (accounts, database, export and the dashboard
  redesign are done); refresh them.
- Rate limits (`http.mjs` `limited()`) are per isolate on Workers, so they are weaker there.
- Passkeys are bound to the hostname; moving domains means users sign in by email and add a new passkey.
- OCR needs iOS 16+ (wasm under CSP); about 6 MB loads on first use. Hindi is opt-in.
- Workers Free has a 10 ms CPU limit per request; passkey checks, push encryption and ZIP export may exceed it.
